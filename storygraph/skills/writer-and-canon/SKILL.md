# 将设计交给正文写作

核对作者选择的场景、视角、文风和结束位置。场景卡若未批准，先让作者审阅；需要新建场景或更改既有场景结构时，打开对应的结构预览。只有作者审阅的场景和披露边界才可交给受保护的 Writer 流程。

输入清单里列清允许 Writer 描写的动作、可见线索和本次写作要求。人物独立推演、后台真相和作者完整对话属于各自的信息范围。续写和局部重写沿用编辑器对正文版本及选区的校验。

正文生成后引导作者比较提案与原稿，由作者决定采用。若新句子可能改变既有设定，另行提出事实候选并保留来源，沿正式审阅路径处理。

在协作模式中，先用 `list_writers` 查看当前已配置且就绪的 Writer，再按场景需要用
`pick_writer(profile_id, reason)` 选择本会话的 Writer，并向作者解释理由。只使用工具真实返回的
连接 ID，不猜测模型、计费方式或账户。这个选择不会改变全局任务分配，也不会调用 Writer；
作者仍需明确执行受保护的正文写作入口。讨论、审阅和正文证据回填模式均不可选择 Writer。
