# 0.3.0 作者协作验收

验收日期：2026-11-01 至 2026-11-02。当前为本地候选版本；已发布及已安装基线仍为 v0.2.0。本记录不表示已通过 GitHub 发布或完成软件内升级。

## 本轮目标与结果

主 Agent 负责根据灵感、选定素材及作者反馈，设计人物认知、行动逻辑与读者披露。框架负责检索、精确引用、局部修改、隔离输入、版本与依赖检查；不以硬编码剧情规则替代创作判断。

以下真实作者协作闭环已通过：

1. 从不完整底稿开始，讨论并区分已决定的后台事实、角色信念和未定动机。
2. 提出、修订和明确采用完整设计；局部修改保留未涉及的字段与原文证据。
3. 分别用独立请求推演两名角色。妹妹输入不含实际藏处或姐姐的私下判断；姐姐只获得她被授权知道的内容。主 Agent 与作者筛选建议，未把推演选项自动当成事实。
4. 在界面中审阅最小场景结构，创建试写场景，预览并编译实际 Writer 输入，再生成正文提案。
5. 正文经独立阅读与当前版本语义检查后，明确保存为 Draft。
6. 框架预读所选精确 Draft，批量定位原句；主 Agent 用三次模型调用提出六条读者呈现记录、五条带引文的角色获知记录。版本、全文哈希和 UTF-16 范围全部核对通过。
7. 在此基础上规划依赖第一场的第二场；作者改变姐姐的主观判断后，影响分析列出两张设计卡及已保存正文。旧 Writer 边界被后端拒绝，未继续沿用。
8. 清理角色文本中的作者备注，复核未改内容的下游卡，明确更新正式场景计划并重新编译边界。两场均恢复批准状态，原正文未改，最新语义报告通过且实际读取时仍为 current。

最终试用项目含 **10 项设计条目、2 张批准的场景卡、6 条读者呈现记录、5 条新增有原文引文的获知记录**。第一场正文实际为 **659 字符（516 汉字）**；800 是场景预算，不是已生成字数。第二场仅完成设计，未生成正文。

这不是重新生成五十万字正文的验收。既有五十万字级框架验收单独记录在 [0.2.0 验收记录](acceptance-0.2.0.md)。本轮证明的是作者协作、信息边界与变更复核的有限闭环，不承诺模型永不出错或所有长篇都无需人工审阅。

## 可审查的框架行为

- 创作设计独立于 Graph canon。采用设计、应用场景计划、授权 Writer、采用正文和正式事实审阅各有明确边界。
- 当前设计和待审版本均可局部修订。仅修改现有字段的工具无需模型抄写整张卡；框架生成完整待审快照，保留未提及内容。
- 同内容的场景复核具有明确卡片目标；新空操作不能冒充审批申请。历史空记录仍可读取和拒绝，不被改写。
- 角色推演使用独立视图和固定问题种类；Writer 不接收完整作者对话、后台真相、其他角色档案或私留推断。
- 来源、canon、语言、会话版本、Draft 与已编译边界均有新鲜度检查。跨项目引用、悬空设计引用和过期证据被拒绝。
- 已完成输出的格式或指定结构校验错误，在原回合额度内最多修正一次。主调用、子调用与修正共享上限；不确定结果、网络、鉴权、限流或版本冲突不自动重试，不更换模型。
- 精确引文由框架定位。模型不能凭估算位置、旧回合引用或另一个 Draft 的引用生成证据；获知建议仍需作者审阅。
- 历史持久化并可分页检索；显示窗口不等于全部历史。长对话与当前设计有独立滚动区，复核提案即使没有创作字段差异也展示完整目标卡。

## 真实调用与限制

本轮使用已授权的 DeepSeek 官方连接，主 Agent 与语义检查采用 Pro 对照，正文样本由 Flash 生成。没有据此给模型作总体性能排名。**54 次真实调用全部已结算用量；保守记账 11.330262 元，上限 50 元，未结算调用为 0。** 所有失败及编码试用失误均保留并计费，未复用或重置上轮预算。

费用守护在每次主/子调用前核对余额并预留上界；按 2026-11-01 核对的[官方峰值费率](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)及缓存未命中估算，预留另含 25% 余量。上述保守记账不是账单精确扣款。

真实试用发现并处理了格式错误、局部编辑清空字段、未采用方案之间的悬空引用、作者备注进入角色文本、未发生的取锁动作以及空操作假复核等问题。角色建议还曾擅加父亲生死或提出提前透露藏处；这些建议被排除，未进入接受的正文。最终结论依据持久数据、实际模型输入、原文引文和独立阅读，不依据模型自述“已经改好”。
