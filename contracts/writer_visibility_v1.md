# Writer Visibility Contract v1

Writer visibility is a local author-controlled disclosure boundary, separate from canon. Policies are versioned in the workspace Proposal SQLite database, never in Graph properties. Saving a policy does not change canon, character knowledge, PLAN fingerprints, Drafts or reader history.

## Policy and source binding

`WriterVisibilityPolicy` has `contract_version: writer_visibility_policy_v1`, explicit `access_mode` (`surface`, `pov`, `omniscient`), `surface_plan`, approved `characters`, `visible_claims`, `writer_style`, `reader_presented` and private `expected_reader_inference`. Project defaults and whole-scene overrides are supported. A scene override replaces the default; it does not silently merge disclosures. Clearing a scope appends a tombstone and retains history. Writes require `expected_version` CAS; scene writes also require the current `expected_source_context_sha256`. The source fingerprint covers the full author Context Pack except ephemeral build/budget presentation and visibility metadata. Project templates resolve against each current scene. Stale or invalid sources fail before model construction.

The surface plan is an explicit literal or an author-selected `current_scene_summary` template. Approved Scene summary is not automatically disclosure permission. Claims are literal author-authorized expressions, not canonical facts or automatic knowledge grants. Their `phase` (`entry` or `during_scene`) is preserved. Belief is a subjective proposition, never labelled false to the Writer; it is allowed only for the current POV in `pov` mode. `surface` forbids private belief; `narrator_fact` requires `omniscient`. Omniscient mode still permits only selected claims, never the entire database.

Characters bind internally to same-project canonical Characters and require explicit public names. The Writer receives opaque local handles and these approved names, not semantic IDs, dossier text, private knowledge, reference paths or other characters' private claims. Writer style is an explicit capsule. A `profile_projection` records and validates the canonical profile ID/hash and requires every nonempty capsule field to equal the effective source field (an explicit subset is allowed); `author_literal` makes no such claim. Neither changes the canonical StyleProfile. Preview and semantic review expose the capsule and its origin so local settings cannot silently replace Agent style authority.

## Reader records

Reader-presented references bind a same-project Draft ID, exact version, whole-text SHA-256, UTF-16 start/end, exact expected text and presentation (`narration`, `character_statement`, `clue`). Local store lookup is the only resolver; arbitrary files, URLs and foreign-project sources are rejected. These records and expected inference remain author-side and do not automatically become Writer-visible claims, editing permission or established reader inference. Unknown reader knowledge remains unknown.

## Runtime boundary

Protected projects (semantic-review-required or approved long-form) serialize `writer_visibility_required`. Their full author Context Pack retains canon for inspection/review, while an excluded runtime sidecar holds the resolved policy. A missing sidecar after serialization does not downgrade protection: prose generation blocks. API and Writer preflight both enforce the boundary before provider calls. Preview returns actual Writer messages, not a UI-only redaction. Explicit legacy projects retain the old unisolated message path and are labelled `legacy_unisolated`; no isolation guarantee is made for that path.

Only approved surface plans, claims, voice and explicitly authorized per-request editing inputs may enter protected prose messages. Raw dossiers, unknown Secret names/IDs/text, future foreshadowing answers, full presets/rubrics and additional references are not appended. Extra sources and web search are not implicitly approved by an editing action. Protected composition into unplanned new Scenes blocks with the route to generate/adopt scene plans before per-scene writing.

Scene semantic review continues receiving full author canon/style plus an explicit narrative disclosure constraint, including current policy and reader-source bindings. The constraint enters scene report freshness and adoption checks. Missing/stale policy cannot be cured by an old passing report. No-policy legacy reports and PLAN inputs retain their previous optional-argument fingerprint behavior. Policies never recertify old responses or alter parser acceptance.

## API

`GET/PUT /projects/{project_id}/writer-visibility` and `GET/PUT /projects/{project_id}/scenes/{scene_id}/writer-visibility` inspect/save local policies. `POST .../writer-visibility/preview` is read-only and makes no model call. Saving requires generation permission; preview/read require read permission. API validates same-project scope, CAS, source freshness and exact reader spans. The Web editor and CLI writer use the same workspace policy store; CLI does not create disclosure permission implicitly.


Per-request `prose_input_grants` are separate from saved policies and ReaderPresented. A prose button explicitly authorizes the current instruction (`instruction`, exact stripped `instruction_sha256`) and its selected editing target: `target: none|draft|selection`, pinned `draft_id`, `version`, whole-text `text_sha256`; selection additionally pins UTF-16 `start`, `end`, `expected_text`, `offset_unit: utf16`. Owner, saved snapshot, version, hash and span are verified before provider construction. Selection sends only that span; continuation/full revision sends the bounded target Draft without silent truncation. Sources, search, history and presets are not implied grants. `POST .../agent-discussion/preview` accepts the identical request and returns the protected action's actual messages without a model call. The Web preview and prose buttons construct the same request; preview adds no confirmation requirement. Legacy unprotected prose keeps its prior complete context behavior and is labelled `legacy_unisolated`.

A project template is projected onto the current scene cast (required Characters plus POV). An offstage public name needs the explicit `allow_offstage_name` flag and same-project Character validation; the template does not silently disclose all project cast.

Rule-based draft templates cannot honor the protected projection and fail with `writer_visibility_rule_based_unsupported` before writer construction at API prose entrypoints. The response directs the author to configure an LLM writer and preview the scene policy. Review-only workflow resume proceeds from human review to END and does not perform a new prose call or require a current generation policy.

Existing Scene `must_include` values are literal generation constraints, not automatically disclosed context. Protected prose must explicitly authorize these literals through its surface plan or claims; otherwise preflight reports a policy gap before provider construction. Output literal checks remain in force. Approved scene summaries do not automatically become literal `must_include` values.

LangGraph checkpoints never serialize live policy/source resolver callbacks. Build checkpoints persist the author-source SHA-256, required marker and policy fingerprint (plus a public build-step isolation marker). Before prose generation, the current Builder re-resolves that exact scene, frozen budget and author refs; only matching source hash, required marker and policy fingerprint permit reattaching a fresh runtime sidecar. Changed/revoked policy, changed source, invalid or missing new-format markers fail closed before generation. Historical unconfigured checkpoints retain legacy behavior only while the current scene remains unconfigured and its author source is unchanged. Review-to-END resume does not generate prose.

API compatibility: `agent-discussion` retains its compact `agent_preset` snapshot as configured metadata. `agent_preset_role` (`configured_only`, `transmitted`, `none`) and `agent_preset_transmitted` distinguish actual transport. Strict prose proposal notes and `writer_visibility_policy` source refs identify the policy fingerprint and approved style origin and explicitly state that the configured preset and author discussion history were not transmitted. Legacy/discussion preset transmission and its original provenance remain unchanged.
